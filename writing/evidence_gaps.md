# Границы доказательств

| Основание | Что осталось открытым | Что нужно для проверки |
|---|---|---|
| SOURCE, историческое описание пермского пилота [ИСТ] | Текущая конфигурация зоны и наличие автоматического считывания UNKNOWN | Инвентаризация конкретных устройств, регламент, схема привязки к документам |
| CONTEXT, разделы 1-13 и 18 пользовательского файла | Ранние варианты платформ, старые цены и гипотезы ошибок имеют собственные даты и основания | Актуальная архитектура участка, сопоставимые коммерческие условия |
| ASSUMPTION, длительность рейсов, кадровые ресурсы и качество [ПРОТ] | Работа при иной геометрии, составе смены и правилах выпуска | Замер рейсов и причин блокировки по сменам и группам товара |
| MEASURED_SIMULATION, WEPAStacks и парные повторы [ДАН, СЕР] | Внешняя валидность и долгосрочный дрейф потока | Независимая хронологическая выборка с исследуемого участка |
| INTERPRETATION, защитный критерий H2 [КОНТРОЛЬ] | Четыре колонки нарушений записаны константами. Для всей серии есть проверки состояний при исполнении, но отдельный детектор частоты нарушений отсутствует | Независимый анализатор по переходам; при отсутствии подробного журнала восстановить его под исходным fingerprint. При обнаружении нарушения пересчитать статус H2 |
| MEASURED_SOFTWARE, Odoo [ОДУ] | Сверка использует проекцию фона, а демонстрационный API и модель по-разному освобождают буфер | Проверить последовательность выезда на полном буфере через пользовательский интерфейс |
| CALCULATED_SCENARIO, экономика [ЭКОН] | Порог CAPEX и окупаемость при заданном OPEX не определены | Завершённая сопоставимая работа, состав смены, стоимость внедрения и поддержки |

Для чтения эффекта по времени достаточно парных разностей [ГИП]. Для утверждения о снижении затрат предприятия требуются данные о том, как меняются оплачиваемые часы. Для утверждения о качестве промышленного учёта нужны фактические ошибки и независимая сверка остатков.
