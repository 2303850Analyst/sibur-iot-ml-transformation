# Стенд V3.2

Измерения выполнены на домашнем ПК, Intel Core i5-14400F, 10 ядер и 16 логических процессоров, память 32 ГБ, SSD Samsung 990 PRO. Docker работает через WSL2. Лимит памяти Docker при проверке составлял 15,51 ГиБ. Пользовательского файла .wslconfig при старте не было. Работающие контейнеры сохраняли своё состояние. Основные Parquet находятся в Linux-томе wms_v32_results, отдельный том с кодом подключён к исполнителю только для чтения.

На одинаковом наборе из восьми технических заданий 4 процесса отработали за 28,29 с, 6 за 24,22 с, 8 за 23,75 с. Последние два режима различаются примерно на 2%, поэтому выбран режим с шестью процессами. Минимум свободной памяти Windows по выборочным замерам во время этого теста составил 6 142 МиБ. Оценка места под основную модельную серию по среднему размеру пилотных разделов - около 127 ГБ. Резерв на диске - 100 ГБ. Температура ядер не измерялась. Обработчик проверяет сигналы Windows о нехватке RAM или диска и может снизить параллельность, не меняя параметры модели.

Исходный дизайн сверялся с обоими реестрами AS-IS и полными декартовыми планами. Хеши 10 390 исходных файлов V1/V2 сравнены с имеющимся реестром. Для старых V3-пилотов сделан отдельный снимок 138 файлов; он служит базой для последующих сверок. При отсутствии прежнего независимого хеша он не подтверждает всю историю файлов.

Время программного события получено на локальных Odoo 19 и Mosquitto. Активная ручная часть хранится отдельно. Где пакет фиксировал механизм автоматизации без численной длительности остаточной ручной проверки, значения приняты как сценарные до пилотного сравнения. Точные значения, правила и хеш профиля сохранены в freeze.json и FREEZE_READY_RU.md.
