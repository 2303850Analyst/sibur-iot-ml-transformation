# WMS V3.2 — окончательный объединённый комплект для Codex

**Самый главный файл:** `01_MASTER_PROMPT_V3_2_NIGHT_RU.md` — вся спецификация V3.1 + V3.2 + настройка ПК/Windows/WSL/Docker + ночной запуск, в одном документе. TXT идентичен MD.

**Статус:** подготовленный протокол; ни один основной запуск A/B/C этим архивом не выполнен. Старые пилоты считаются техническими и НЕ относятся к новой числовой базе.

## Обязательные научные объёмы

- A: все 128 масок × 6 сценариев × 3 нагрузки × 20 seed = **46 080 сквозных SimPy-запусков**.
- B: все 128 × 6 × 3 × 3 = **6 912 событийных Odoo replay**, **не** длительный стресс, все 20 ролевых сессий и конкурентные транзакции.
- C: 25 заранее фиксированных strength-3 масок × 6 × 3 × 3 = **1 350 стресс-окон**, реальные 20 пользователей, 60+15 секунд на окно; минимум ~28 ч 7 мин 30 с фиксированного времени на последовательном хосте.

**Производственный AS-IS:** WMS + ТСД, без складского IoT и ML, без упрощённых сквозных сценариев. Это допущение. Новый baseline JSON содержит временные распределения 25 операций и явные роли.

## Ключевые материалы

- `protocol/ASIS_BASELINE_PARAMETER_FREEZE.json` — 25 исходных времён и модель человеческого фактора; по умолчанию треугольные распределения 0.7×/1.0×/1.3×, кроме реальных физических операций.
- `protocol/ASIS_25_OPERATIONS.csv` — читаемые времена на операцию.
- `protocol/RESULTS_DATA_CONTRACT_V3_2_CANONICAL.json` — обязательные имена полей, в том числе P01–P25 для КАЖДОГО поступления.
- `protocol/MEASUREMENT_METHOD_RU.md` — формулы длительности, трудоёмкости, техники и экономики.
- `environment/00_ENVIRONMENT_SETUP_RU.md` — измерение и настройка ПК i5-14400F / 32 ГБ / Samsung 990 Pro / RTX 3060; WSL RAM 22 ГБ / 12 logical / 4 swap; безопасность Docker.
- `execution/NIGHT_RUN_AGENT_RU.md` — порядок запуска и ускорение 6–8 CPU workers, checkpoint.
- `execution/generate_v3_2_plan.py` и `execution/plans/` — воспроизводимый полный план для контуров A/B/C.
- `examples/STAGE_COMPARISON_TEMPLATE.csv` — формат обязательной таблицы 25 операций C000 против любого варианта с очередью, работой людей/техники и эффектом.
- `reference/01_PROMPT_V3_1_FULL_RU.md` — историческая полная спецификация, если понадобится аудит; приоритет у нового master.

## Как использовать

1. Приложи ZIP к локальному проекту `wms_inbound_experiment`. Прочитай целиком `01_MASTER_PROMPT_V3_2_NIGHT_RU.md`.
2. В отдельном preflight установи, что оборудование и контейнеры работают; не удаляй тома, не перезапускай WSL без разрешения и сохранённого состояния.
3. Заморозь AS-IS, перечень операций и сохраняемых ручных действий TO-BE **до** первой основной серии. Подтверди точный replay хотя бы 10 заранее выбранных случаев.
4. Запускай A (приоритет на ночь) → B (после A) → C (на отдельной свободной нагрузочной фазе). Оставшиеся после ночи задания продолжаются по checkpoint/resume. Не обещай, что все контуры успеют за ночь.
5. Каждый run и каждый case должны содержать подробную развертку 25 операций, занятость человека и оборудования. Результат по отдельному case всегда извлекается через `case_replay_tool.py`.

**На компьютере пользователя ничего не изменено.** Этот пакет даёт агенту инструкции для локальных действий после инвентаризации и необходимых разрешений.
