# WMS V3 — промпт и проверенная матрица полного эксперимента

**Статус: задание подготовлено; V3 не запускался.** Проверена только комбинаторика будущих испытаний.

Главный файл: `01_PROMPT_V3_FULL_RU.txt` (то же содержимое в Markdown). Его можно целиком передать агенту в существующем проекте. В промпте есть контекст, 25 операций, 7 модулей, правила единообразия, испытания Odoo/ТСД/IoT, статистика и состав отчёта.

20 пользователей — параллелизм, а не число физических погрузчиков и не число повторов. Обе серии полностью сбалансированы по вариантам, но имеют разные часы и назначение. Их длительности не объединяются в одну метрику.

Процессные параметры, которых нет в фактических данных, должны получить явный сценарный статус до запуска. Предыдущие результаты не подставляются в V3, а отсутствие датчиков на реальном предприятии не объявляется фактом.

## Сообщение агенту

```text
Работай в существующем проекте wms_inbound_experiment.
Прочитай и выполни 01_PROMPT_V3_FULL_RU.md полностью.
V3_PROTOCOL.json закрепляет размер матрицы и правила измерения.
Сохрани V1/V2 без изменений. Сначала проверь реальные исходники и данные,
реализуй отсутствующие части 25-операционного процесса и модули Odoo,
затем выполни pilot → freeze → полную матрицу → аудит → единый отчёт.
Не заменяй реальную Odoo симуляцией и не называй планы результатами.
Не останавливайся на плане; при объективном ограничении сохрани checkpoint,
точное покрытие и команду продолжения, не сокращая тайно матрицу.
```

## Файлы

- `01_PROMPT_V3_FULL_RU.md/.txt` — самодостаточное техническое задание.
- `V3_PROTOCOL.json` — фиксированные параметры дизайна, операции и модули.
- `V3_CONFIGURATIONS_128.json` — полный набор масок с понятными названиями.
- `generate_plan.py` — генератор и валидатор матрицы, без сторонних зависимостей.
- `plans/configurations.csv` — порядок отображения: без ML, затем с ML.
- `plans/run_manifest.csv` — все запланированные имитационные запуски.
- `plans/live_manifest.csv` — все запланированные live-испытания.
- `plans/plan_validation.json` — проверки количества и равенства покрытия.
- `SOURCE_NOTES.md` — что взято из существующих материалов и что задано новым протоколом.

Команда повторной проверки плана: `python generate_plan.py`.

## Важное ограничение

Полный перебор большой. Пакет обеспечивает одну однозначную постановку для автоматического исполнителя, а не гарантию завершения всей серии в рамках одной короткой сессии. Ни один сокращённый, выборочный или только симуляционный прогон не должен получить статус полного выполнения.
