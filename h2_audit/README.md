Дата отчёта 19.11.2026. Статус **VERIFIED_FOR_H2_SIMULATION_SCOPE** относится к S1/L2, вариантам B и C, seed от 1000 до 1019. Проверены 40 журналов, 3 957 630 строк с учётом прогрева и завершающих суток. В 38 случаях подробный журнал восстановлен впервые в рамках этой проверки. Для двух контролей seed 1000 новые сжатые журналы побайтно совпали с исходными.

## Как получен вывод

Исходная серия подключена к контейнеру только для чтения. Образ выбран по идентификатору из исходного environment.lock.json. Тег на машине уже указывал на другой образ. Проверены SHA-256 каждого элемента списка заморозки, сжатого и распакованного исходного набора, а также fingerprint с фактическими версиями Python и пакетов. Для каждого запуска заново построены входы функциями sample и campaign. Вариант C использовал сохранённую модель L2. Сопоставлены все ключи и значения исходных метрик и байты всех перечисленных в исходном манифесте файлов, включая Parquet и карту дней.

Новый анализатор ledger.py читает события в порядке записи. Он ведёт баланс каждой физической единицы, права на адрес, состояние резерва, транзита и подтверждения, а также очередь внешних заявок. При выезде из карантина паллета числится в пути, а исходный адрес удерживается до конца рейса. Регистрация проверяется по идентификатору паллеты, партии, количеству и физическому поступлению. Отклонённая исходящая заявка не изменяет остаток. Независимо сверены начальный запас, доступный остаток по SKU, терминальные статусы качества и времена регистрации и первичного размещения каждой паллеты с исходной таблицей.

Начальный статус качества задан списком held. Только для такой паллеты допустим один модельный external_release через 7200 секунд после поступления. Источник полномочий в этом аудите - правило модели. Для выводов о реальных правах пользователей нужны журналы действий Odoo. Поля нарушений из исходной сводной таблицы использованы только при проверке точности воспроизведения. Вердикт вычислен по журналам.

Отдельно воспроизведены парные разности и 5000 перевыборок по целым seed. Выигрыш C относительно B составил 7,90 с, интервал 97,5% от 5,20 до 11,04 с. Просрочка подготовки выросла на 0,591 п.п. Её верхняя граница 97,5%-го интервала составила 0,793 п.п. при пределе 1 п.п. Предусмотренные для H2 условия выполнены в указанной области проверки.

## Что читать

- h2_sidecar.json - итог аудита, статистика и область вывода.
- coverage.csv - идентификатор и результат каждого запуска, число строк, контрольные суммы и четыре счётчика.
- environment.json - версии, fingerprint и проверенные хеши входов.
- runs/<run_id>/events.jsonl.gz - полный журнал. В initial.json.gz ключи inbound и outbound сохраняют исходные списки по порядку. Номер строки inbound с нуля задаёт pallet. В cells записаны пары адрес и SKU начального запаса.
- В каждой папке manifest.json - копия первоначального манифеста. В reproduction.json находятся три хеша для каждого исходного файла, а в audit.json - счётчики обработанных операций и результат событийной проверки.
- test_ledger.py и tests.log - 16 прошедших локальных проверок этого анализатора, из них четыре на мутациях настоящего журнала. Код ранее упомянутого стороннего анализатора в приложении к ТЗ отсутствовал.
- reference/artifacts в архиве содержит исходные данные для независимого повторного запуска audit.py, включая исходные таблицы по паллетам всех 40 запусков.

## Повторная проверка

Распакуйте ZIP. Для audit.py подключите распакованный каталог к /audit, его подкаталог reference к /series только для чтения. Запустите python /audit/audit.py в образе из environment.json. Анализатор перезапишет только результаты аудита в распакованной копии. Тесты запускаются командой python -m pytest /audit/test_ledger.py.

Для полного повторного восстановления событий вместо reference подключите исходный полный каталог series_py312 к /series только для чтения, выберите рабочую папку /series и задайте PYTHONPATH=/series, OMP_NUM_THREADS=1, OPENBLAS_NUM_THREADS=1. Поместите копию файлов .py из архива в новый выходной каталог, подключите его к /audit и запустите python /audit/reproduce.py, затем python /audit/audit.py. Код воспроизведения использует готовую замороженную серию без обучения.
